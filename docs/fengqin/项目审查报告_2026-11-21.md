## 二、高优先级问题（P1：真实 Bug、安全隐私边界与线上风险）

### P1-1｜生产包与开发环境登录页行为分叉（Terser 顶层混淆导致生产静默回退旧登录页）
- **位置**：`src/tenant/app.js:556`、`src/tenant/yx.js:39`、`scripts/build.mjs:101`
- **核查事实**：
  - `src/tenant/app.js:556` 写为 `if (globalThis.yxLoginPage) return yxLoginPage();`。
  - `scripts/build.mjs` 使用 Terser `module: true, mangle: { toplevel: true }` 压缩 `dist/assets/tenant.js`，顶层声明 `function yxLoginPage()` 被混淆为短标识符（本次构建产物实测为 `if(globalThis.yxLoginPage)return Kt();`），且未挂载到 `globalThis`。
  - 结果：**生产环境 `globalThis.yxLoginPage` 恒为 `undefined`**，正常访问 `/login` 实际渲染的是旧渠道版 `app.js` 的 `login()`（`.login-layout`、`POST /api/login`），而非 `yx.js` 中新设计的钢琴图分栏登录页 `.fq-login`（`POST /api/auth/login`）；而开发/源码模式下 `yxLoginPage` 挂在全局，渲染的是新页。拆分到 `/assets/tenant-fonts.css` 的 `fq-photo.css` 在线上常规登录也基本处于空转状态。
- **建议（Claude）**：明确生产要展示哪一版登录页——若使用新钢琴图登录页，将 `globalThis.yxLoginPage` 改为直接调用或 `typeof yxLoginPage === "function"`，并移除废弃分支；后续避免在 Terser `toplevel: true` 打包模式下用 `globalThis.<顶层函数名>` 判断函数是否存在。

### P1-2｜`read-batch` 合批读取报错时未读取统一错误契约 `message`，界面暴露英文错误码
- **位置**：`src/tenant/app.js:428, 437`（对比 `src/tenant/app.js:469-471`、`src/server/worker.js:1022-1025`）
- **核查事实**：
  - 后端 `normalizeResponse` 将 API 错误统一规范为 `{ error: "forbidden", code: "forbidden", message: "中文提示" }`。
  - 单请求 `apiRequest()` 已正确按 `result.message || result.error` 提取中文提示；但批量读取 `flushBatch()` 仍只取 `result?.error` 与 `body.error`，**完全忽略 `body.message`**。
  - 随着 PR #11 将 `read-batch` 白名单扩充至 40+ 路径，一旦合批中任意子请求返回 400/403/404/429，用户会看到 `"forbidden"`、`"not_found"` 等英文机器码。
- **建议（Claude）**：将 `flushBatch()` 的错误解析与 `apiRequest()` 对齐（优先 `body.message || body.error`，并统一提取 `code = body.message ? body.error : body.code`），并补充对应断言测试。

### P1-3｜会话被远程撤销触发 `401` 时未清理 PWA 离线缓存与启动预取提示
- **位置**：`src/tenant/app.js:290, 427, 467`、`src/tenant/pwa/sw.js:52-75`
- **核查事实**：
  - 主动登出（`api("logout")`）会调用 `offlineClear()`；换人登录（`rememberLogin`）会清理他人缓存。
  - 但当老师/学员账号被停用、重置密码、踢出设备或主管执行**全量备份恢复（清空所有会话）**时，客户端在 `apiRequest`（467 行）或 `flushBatch`（427 行）收到 `401` 后直接跳转 `/login`，**未调用 `offlineClear()` 也未清理 `fq_boot_hint`**。若随后在断网状态下通过 SW 缓存的 `/app/` 外壳进入，残留的 `fq_offline_v1` 仍可在 14 天有效期内被展示。
- **建议（Claude）**：在非登录请求收到 `401` 时，跳转前同步执行 `offlineClear()` 并移除 `localStorage.fq_boot_hint`。

### P1-4｜全量备份打包与自动备份下载存在 $O(N^2)$ 整包重复序列化风险
- **位置**：`src/server/full-backup.js:24-27, 73, 155, 169`
- **核查事实**：
  - `checkSize(payload)` 对整个 `payload` 执行 `textBytes(JSON.stringify(payload)).byteLength`。
  - 该函数在图库媒体读取循环（73 行）及自动备份分页/媒体装配循环（155、169 行）内**每迭代一次即全量重序列化整个 `payload`**。当存在数十至上百张图片或较多分页接近 10–16 MiB 时，累计临时字符串与 UTF-8 缓冲区分配呈 $O(N^2)$ 膨胀，在 Cloudflare Workers 128 MiB 内存与 CPU 限制下极易远低于 16 MiB 上限即 OOM 或超时。
- **建议（GPT/Codex）**：循环中改为增量累加每个新增条目/分片的字节估算值提前拦截超限，循环结束后再做一次整包精确字节校验。

### P1-5｜全量恢复单批事务体量较大，尚缺真实 D1 + EdgeOne 链路压测
- **位置**：`src/server/repo.js:1783-1873`（`commitFullRestore`）
- **核查事实**：
  - 一次恢复提交将 71 张表的 `EXCEPT` 并发校验、全部触发器 `DROP`/`CREATE`、71 表 `DELETE` 与全量 `json_each` 分片 `INSERT` 打包在**单个 `db.batch(ops)`** 中（空库已超过 220 条 SQL 语句）。
  - 本地 `node:sqlite` 模拟器不模拟远程 D1 HTTP 请求体大小、单批执行超时或 EdgeOne 回源超时。目前尚无带真实数据量（例如数千行记录 + 数十张图库图片）的线上/预发恢复压测记录。
- **建议（GPT/Codex + 主人）**：在独立测试环境或上线低峰对真实 D1（并经 EdgeOne 切流后）执行一次带代表性数据量的全量导出与恢复演练，明确线上实际安全体量边界。

## 三、中优先级问题（P2：架构隐患、缺口与第三期联动风险）

### P2-1｜第三期决策 #14（主管编辑机构名称/Logo/联系说明）存在 4 处前后端联动陷阱
根据未合并分支 `design/redesign/DECISIONS.md` 第 14 条，主管将可直接编辑机构名称、Logo 与联系说明。当前代码存在四处必须协同处理的地方：
1. **前端强覆盖名称**：`src/tenant/app.js:1831` 写死 `brand.display_name = "枫琴教务中心"`，无条件覆盖 `/api/public/brand` 返回值（`yx.js`、`fq-teacher.js`、`manifest.webmanifest` 等也有多处字面写死）。
2. **24 小时本地品牌缓存**：`src/tenant/app.js:1818` 将 `fq_brand_v1` 缓存在 `localStorage` 24 小时，保存品牌后需主动清缓存并刷新 UI。
3. **现有品牌写接口字段白名单**：`src/server/tool-settings.js:757-783` 已有 `PATCH /api/settings/brand`，当前仅放行 `primary_color` 与 `qr_image_id`。建议直接扩展该接口（新增字段仅主管可改、校验图片大小/MIME、递增 `version` 以自动刷新 `/api/public/brand/logo?v=<version>` 不可变长缓存、写审计日志），避免另起重复接口。
4. **`contact_text` 字段加密一致性（关键）**：`tenant_branding.contact_text` 在数据库中为 **AES-GCM 密文**（上下文 `tenant.id + ":contact"`，见 `src/server/todo-actions.js:198-202`）。写接口**必须加密存储**，若误写明文将导致续费通知接口解密报错。

### P2-2｜第三期决策 #2（学员手机尾号搜索）与 #9（迁移 `0033` 线索回访表）前置设计提示
