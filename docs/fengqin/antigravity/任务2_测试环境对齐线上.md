# Antigravity 任务 2：测试环境对齐线上 Cloudflare

先读 `AGENTS.md`（协作规则）与 `docs/fengqin/接口变更.md` 末尾几节。分支 `antigravity/test-parity`，从最新 `main` 开出。审查：GPT。开工前在 `docs/fengqin/任务板.md` 把任务 2 改为「进行中」。

## 背景
本地测试用模拟的 D1（`tests/d1-emulator.mjs` + Node SQLite）和 R2（`tests/r2.mjs`）。已经有两次线上故障是「模拟比线上宽松」造成的：
1. R2 `list({cursor: ""})` 线上报 `Continuation token is not valid (10023)`，模拟器不报 → 定时备份自部署起每次失败。
2. D1 每个 compound SELECT 最多 5 段，本地 SQLite 允许 500 段 → 待办收件箱整页 500、全量备份/恢复的行数统计也会失败。

两处都已修复并在模拟器里补上限制。本任务目标：**系统性找出其余差异，补进模拟器，并在真实环境演练测不到的部分**。

## 要做的
1. **D1 限制清单**：对照 Cloudflare D1 官方文档的 limits 与 SQL 兼容性说明，逐项确认模拟器是否覆盖（单条 SQL 长度、参数个数、compound 段数、表达式深度、LIKE/GLOB 模式长度、单行/单值大小、batch 条数与总大小、单次查询时长/CPU、不支持的 PRAGMA 与语句、事务语义与 `BEGIN` 限制、`defer_foreign_keys` 行为、`sqlite_master` 可读性等）。未覆盖且项目可能触发的，补进 `tests/d1-emulator.mjs`，每项配一个最小测试证明「超限时报错、不超限时通过」。
2. **R2 行为清单**：同样对照 R2 Workers API 文档（`list` 的 cursor/limit/prefix/delimiter、`delete` 批量上限、`put` 大小与 httpMetadata、`get` 的 range/onlyIf、对象不存在时的返回值）补进 `tests/r2.mjs`。
3. **真实 D1 演练（只用测试库，绝不碰生产）**：在 Cloudflare 上新建一个**临时测试 D1**（名称如 `fengqin-parity-tmp`），按顺序执行 `migrations/0001`–最新，跑：
   - 全量恢复 `commitFullRestore` 路径会执行的 `PRAGMA`、`DROP TRIGGER`、按 `sqlite_master` 重建触发器等 DDL；
   - 全量备份导出 → 预览 → 确认恢复的完整往返（可用 `wrangler d1 execute` 或临时 Worker）。
   记录结果到 `docs/qa/线上一致性.md`。演练完删除临时库。Cloudflare 访问方式与账号由用户提供；生产库 `fengqin-crm-prod` 只允许只读的 `EXPLAIN`，不得写入。
4. 若发现新的线上不兼容，**不要直接改 `src/server/`**：在 PR 里附复现测试（模拟器里会失败的那条），交给 GPT 修。

## 完成标准
- `npm run build && npm test && TEST_BUNDLE=1 npm test` 全绿（新加的限制若让现有测试失败，说明发现了真实问题：在 PR 里列出，不要放宽限制）。
- `docs/qa/线上一致性.md`：已覆盖的限制表（来源链接、模拟器位置、测试名）、未覆盖项及原因、真实演练记录。
- PR 描述列出改动的测试文件与发现的问题；任务板更新状态。
