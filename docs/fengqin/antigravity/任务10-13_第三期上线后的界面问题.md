## #13 课程形式合并：小组课 + 集训班 → 班课（前后端，用户已决定：课酬标准一并合并）
用户决定（2026-11-22）：课程形式只保留 **一对一** 与 **班课**；原「小组课」(`group`) 与「集训班」(`class`) 合并为「班课」，**教师课酬标准也合并**为一套。「班级」功能（固定名单，可整班排课销课）不变。

背景：`format` 取值 `individual / group / class`，`group` 与 `class` 在后端逻辑上没有区别（一对一限制 1 人；其余只受人数上限和教室容量限制），唯一区别是教师课酬按形式分别匹配（`src/server/finance.js`、`rebuild3.js`、`credits.js`、`scheduling.js`、`imports.js`、`xlsx.js` 等含 `format`）。表：`course_types.format`、`lessons.format`、`teacher_rates.format`（0003/0006）。

**生产现状（2026-11-22 只读查询）**：`course_types`：group 2 条、individual 2 条；`teacher_rates`：**0 条**；`lessons`：individual 2 节；无 class。→ 现在合并几乎没有历史包袱，须赶在录入课酬标准之前上线。

方案（规范值取 **`group`**，显示名「班课」；`class` 作为旧值别名）：
1. **后端**：
   - 新增 `normalizeFormat(x)`：`individual` 保持，其余（`group`/`class`）→ `group`；所有读取比较、写入校验、课酬匹配、导入导出、AI 上下文、备份恢复处统一使用。写入接口仍接受 `class`（旧客户端、旧备份、旧导入模板），落库一律存 `group`。校验里 `['individual','group','class']` 保持兼容。
   - 迁移 **0034**（编号已在 `docs/fengqin/迁移编号.md` 预留，先改为占用）：`UPDATE course_types/lessons/teacher_rates SET format='group' WHERE format='class'`；同一教师、同一课程、重叠生效期的 `group` 与 `class` 课酬并存时：保留 `created_at` 较晚的一条，另一条标记删除并写进迁移注释说明规则（生产为 0 条，规则只为兼容其他环境/旧备份）。**只改数据，不改表结构**，因此不提升全量备份版本；但恢复旧备份（含 `class`）时必须经 `normalizeFormat` 归一，并加测试覆盖。
   - 历史已结算月份的课酬金额不得变化（用 `rateLocks` 等现有机制核对；加回归测试：合并前后同一批课的应发一致）。
2. **前端**：全前端（`app.js` 2477、`c3.js` 1160/1503、`fq-settings.js` 735、`v2s.js` 483、`v2p.js`/`v2f.js` 的课酬标准页、导入模板说明等，用 `grep` 全量查）：形式下拉只显示「一对一 / 班课」；课酬标准页只显示这两栏；已有 `class` 值的旧数据显示为「班课」。
3. **导入/导出**：Excel 导入模板里「形式」列接受「小组课 / 班课 / 集训班」都映射为班课。
4. 记入 `docs/fengqin/接口变更.md`（新增一节「课程形式合并」）；PR 说明里列出改动的测试。
5. 上线（Claude 执行，需用户授权）：先在生产 D1 执行 0034（只改数据，先记 Time Travel 书签），再部署代码；代码兼容新旧值，顺序反了也不会出错。

## #16 排课逻辑：课程时长是「1 课时的时长」，总时长 = 单课时时长 × 课时数；课时数按 0.5 一档（前后端，**重大逻辑问题，最高优先级**）
用户反馈（2026-11-22）：排课时「时长」选 45、「课时数」选 2，排出来的仍是 45 分钟，却销了 2 节课时。正确语义：**「课程时长」是 1 个课时的时长（30/45/60），课时数为 n 时，这节课实际占用 时长 × n 分钟**（45×2=90 分钟）。另外「课时数」现在可填 1.01 之类任意小数，应改为**按 0.5 一档**（…、0.5、1、1.5、2…，默认 1，上下调节每档 0.5）。

现状（代码）：
- `src/server/scheduling.js`：`duration()`（约 59 行）只允许 30/45/60；`row.duration` 与 `row.units` 各自独立存储、互不乘（约 287–290 行）；冲突检测用 `start + lesson.duration`（约 348–359 行）。`units()`（约 54 行）接受任意正小数。
- 表：`lessons.duration INTEGER`、`lessons.units REAL`，`schedule_templates` 同样有 duration/units，`course_types.default_minutes`（单课时分钟）与 `units_per_lesson`（默认课时数）。
- 前端：`src/tenant/app.js` 约 2485–2487（课程类型「每节课时」`step=0.01`）、约 2755–2756（排课「课时数」`step=0.01`）；`calendar.js`、`v2.js`（新建/编辑课程、固定排课、批量生成、补课）、`fq-schedule.js`、`imports.js`/`xlsx.js`（导入）。

要求：
1. **语义**：新增概念「单课时分钟」`unit_minutes`（30/45/60）。**`lessons.duration` 保持为「这节课占用的总分钟数」**，这样冲突检测、日历、课表图、课酬按课次等所有读取 `duration` 的地方自动正确；写入时 `duration = unit_minutes × units`。具体落库方式（是否新增 `unit_minutes` 列、迁移编号 **0035**，先在 `docs/fengqin/迁移编号.md` 占号）由你设计，但必须满足：①编辑已有课程时能回显「单课时 × 课时数」；②历史数据（现有课程 units 多为 1，duration=30/45/60）不改变；③`course_types.default_minutes` 的含义明确为单课时分钟，排课默认总时长 = `default_minutes × units_per_lesson`。
2. **校验**：`unit_minutes` 只能 30/45/60；`units` 必须是 0.5 的整数倍，最小 0.5；`duration` 总分钟校验改为「单课时分钟 × 课时数」，不再限制为 30/45/60。**0.5 课时 × 45 分钟 = 22.5 分钟不是整数分钟**：默认方案——总分钟数四舍五入到整数分钟（22.5→23），并在表单里显示换算后的结束时间；如果你认为有更好的处理（例如 45 分钟课时只允许整数课时），在 PR 里说明并让用户决定。
3. **前端**：排课、编辑课程、固定排课、批量生成、补课（含「新建目标课时」）、课程类型表单、导入模板：「时长」字段改名「单课时时长（分钟）」；课时数控件改为 0.5 步进（数字输入 `step=0.5 min=0.5`，并有 −/+ 按钮），旁边实时显示「共 N 分钟，HH:MM–HH:MM」；日历、课表图、冲突提示用总时长。课程类型表单「每节课时」同样 0.5 步进，「默认分钟」改名「单课时默认分钟」。
4. **所有创建课程的入口都要走同一套换算**（不要各写各的）：新建课程、固定排课生成、批量生成、补课、导入、AI 排课（若有）；用 `grep "duration"` 全量检查 `src/server/`、`src/tenant/`。
5. **回归测试**：45 分钟×2 课时=90 分钟占用并正确触发冲突（后面 45 分钟内排另一节应冲突）；1.5 课时、0.5 课时；非 0.5 倍数的课时数被拒绝；旧课程编辑不变形；固定排课与补课生成的总时长；课酬「按课时」仍按 `units` 计、「按课次」仍每节一次（课酬结果不应因本改动而变）；备份恢复。
6. **上线**：Claude 执行；迁移前记 Time Travel 书签；生产现有课程只有 2 节（都是 1 课时），影响极小。与 #13（课程形式合并，迁移 0034）都改 `scheduling.js`，**先合并的先上线，后合并者解决冲突**；两个迁移编号不同，互不影响。
