## #10 登录页背景可自定义（前端 + 少量后端确认）
现状：
- 新登录页（`src/tenant/yx.js` 的 `fq-login-side`，样式 `src/tenant/fq.css` 约 326–345 行）的照片来自 `--fq-login-photo`，定义在**延迟加载**的 `fq-photo.css` / `tenant-fonts.css`；`src/tenant/app.js` 为手机提速，窄屏（≤760px）和省流量时**不加载**它，所以手机上背景是纯深色。
- 后端早已支持自定义登录背景：表 `tenant_branding.login_bg`，公开接口 `GET /api/public/brand/login-bg`、`/api/public/brand?lite=1` 返回 `login_bg_url`（`src/server/worker.js` 约 296–340 行）。旧登录页（`app.js` 约 632 行）用到，新登录页没用。设置里「机构与品牌」（`src/tenant/fq-settings.js`、`yx-settings.js` 的 `yxsBrandEditor`）**没有登录背景的上传入口**，需核对 `settings/brand` 的写接口是否已支持 `login_bg`（大小、类型校验沿用品牌图片规则）。

要求：
1. 设置 › 机构与品牌：增加「登录页背景图」上传、预览、恢复默认；仅主管；写审计；大小限制与格式校验沿用 Logo 规则（若后端写接口不支持则补，记入 `接口变更.md`，GPT 恢复后补审）。
2. 登录页：有自定义图就用自定义图，没有就用默认照片；电脑端行为不变。
3. 手机端：不要退回纯深色。默认照片太大（约 45KB base64 内嵌）的话，手机用较小尺寸版本或在登录页首屏之后再加载；自定义图用 `login_bg_url`（带版本号，可长缓存），手机上也显示，但要有尺寸/压缩限制（建议上传时在前端压缩到长边 ≤1600px、≤200KB），避免拖慢登录页。
4. 验收：电脑与 iPhone 13 登录页截图（默认图 / 自定义图 / 未加载完时的底色）；`tools/qa/lp.cjs` 看登录页请求体积，登录页首屏不得因此明显变慢。

## #11 按钮悬停与点击反馈（前端，全站）
现状反馈：很多按钮没有悬停动画，操作上有「怪」的感觉。
要求：
1. 盘点所有可点击元素类型：主按钮/次按钮/幽灵按钮/药丸筛选/图标按钮/卡片行/表格行/导航项/页签/抽屉里的按钮/手机底栏。每类给出统一的状态规范：悬停（颜色或阴影微变，0.15–0.2s 过渡）、按下（轻微下沉或变暗）、键盘焦点（清晰的焦点环）、禁用（降低对比度、`cursor: not-allowed`）、加载中。
2. 规范写进 `src/ui/components.css` 与 `src/tenant/fq.css` 的统一层（用已有变量 `--fq-*`），**不要**逐个页面打补丁；触屏设备不要因悬停样式留下「粘住」的状态（用 `@media (hover: hover)` 包裹悬停）。
3. 尊重 `prefers-reduced-motion`。
4. 验收：写 Playwright 脚本（放 `tests/e2e/` 或 `tools/qa/`）遍历主要页面，对每类可点击元素 hover/focus 并断言样式确有变化；附前后对比截图。

## #13 课程形式合并：小组课 + 集训班 → 班课（前后端，用户已决定：课酬标准一并合并）
用户决定（2026-11-22）：课程形式只保留 **一对一** 与 **班课**；原「小组课」(`group`) 与「集训班」(`class`) 合并为「班课」，**教师课酬标准也合并**为一套。「班级」功能（固定名单，可整班排课销课）不变。

背景：`format` 取值 `individual / group / class`，`group` 与 `class` 在后端逻辑上没有区别（一对一限制 1 人；其余只受人数上限和教室容量限制），唯一区别是教师课酬按形式分别匹配（`src/server/finance.js`、`rebuild3.js`、`credits.js`、`scheduling.js`、`imports.js`、`xlsx.js` 等含 `format`）。表：`course_types.format`、`lessons.format`、`teacher_rates.format`（0003/0006）。

**生产现状（2026-11-22 只读查询）**：`course_types`：group 2 条、individual 2 条；`teacher_rates`：**0 条**；`lessons`：individual 2 节；无 class。→ 现在合并几乎没有历史包袱，须赶在录入课酬标准之前上线。

方案（规范值取 **`group`**，显示名「班课」；`class` 作为旧值别名）：
1. **后端**：
   - 新增 `normalizeFormat(x)`：`individual` 保持，其余（`group`/`class`）→ `group`；所有读取比较、写入校验、课酬匹配、导入导出、AI 上下文、备份恢复处统一使用。写入接口仍接受 `class`（旧客户端、旧备份、旧导入模板），落库一律存 `group`。校验里 `['individual','group','class']` 保持兼容。
   - 迁移 **0034**（编号已在 `docs/fengqin/迁移编号.md` 预留，先改为占用）：`UPDATE course_types/lessons/teacher_rates SET format='group' WHERE format='class'`；同一教师、同一课程、重叠生效期的 `group` 与 `class` 课酬并存时：保留 `created_at` 较晚的一条，另一条标记删除并写进迁移注释说明规则（生产为 0 条，规则只为兼容其他环境/旧备份）。**只改数据，不改表结构**，因此不提升全量备份版本；但恢复旧备份（含 `class`）时必须经 `normalizeFormat` 归一，并加测试覆盖。
   - 历史已结算月份的课酬金额不得变化（用 `rateLocks` 等现有机制核对；加回归测试：合并前后同一批课的应发一致）。
2. **前端**：全前端（`app.js` 2477、`c3.js` 1160/1503、`fq-settings.js` 735、`v2s.js` 483、`v2p.js`/`v2f.js` 的课酬标准页、导入模板说明等，用 `grep` 全量查）：形式下拉只显示「一对一 / 班课」；课酬标准页只显示这两栏；已有 `class` 值的旧数据显示为「班课」。
3. **导入/导出**：Excel 导入模板里「形式」列接受「小组课 / 班课 / 集训班」都映射为班课。
4. 记入 `docs/fengqin/接口变更.md`（新增一节「课程形式合并」）；PR 说明里列出改动的测试。
5. 上线（Claude 执行，需用户授权）：先在生产 D1 执行 0034（只改数据，先记 Time Travel 书签），再部署代码；代码兼容新旧值，顺序反了也不会出错。
