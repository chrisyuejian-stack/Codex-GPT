## 1. 前提检查（在 main 最新提交上）
```bash
git checkout main && git pull
npm run build && npm test && TEST_BUNDLE=1 npm test     # 必须全绿
npm run test:migrations:preflight                        # 迁移预检
```
确认待上线的迁移：`ls migrations | tail`（当前待执行：`0034_merge_course_formats.sql`、`0035_lesson_unit_minutes.sql`；以 `docs/fengqin/迁移编号.md` 为准）。

## 2. 临时库演练（必须先做，尤其是 0035：重建 6 个触发器，生产第一次执行）
1. 创建临时库：`npx wrangler d1 create fengqin-parity-tmp --location apac`，记下返回的 id。
2. 把生产数据复制进去（只读导出，**导出文件含加密后的学员数据，不得提交、不得外传，演练后删除**）：
   ```bash
   npx wrangler d1 export fengqin-crm-prod --remote --output /tmp/prod-export.sql
   npx wrangler d1 execute fengqin-parity-tmp --remote --file /tmp/prod-export.sql
   ```
   （导出已包含表结构与迁移 0033 的状态。若导入因触发器/外键顺序失败，改为：先按 `migrations/0001…0033` 顺序在临时库建表，再导入数据行。）
3. 在临时库按顺序执行 0034、0035：`npx wrangler d1 execute fengqin-parity-tmp --remote --yes --file migrations/0034_merge_course_formats.sql`，再 0035。
4. 核对（临时库）：
   - `select count(*) from course_types where format='class'` = 0，`teacher_rates`/`lessons` 同；
   - `pragma table_info(lessons)` 含 `unit_minutes`，`schedule_templates` 同；已有课程的 `unit_minutes` 非空；
   - `select count(*) from sqlite_master where type='trigger' and name like 'course_limits_%'` = 6；
   - 行数与迁移前一致（course_types、lessons、teacher_rates、students）；
   - **触发器行为**：对临时库用 SQL 试几条（插入/更新课程类型 units_per_lesson=1.5、1.3、0.4；课时数 0.5 的课程），确认合法的通过、非法的被 `course_duration_or_units` 拦住，已有旧数据仍能正常更新其他字段。
5. 用临时库的结果写进 `docs/fengqin/进度_Antigravity.md` 和 `docs/qa/迁移演练_<日期>.md`（只写结论与计数，不贴任何数据内容）。
6. 演练完**删除**：`npx wrangler d1 delete fengqin-parity-tmp`，并 `rm /tmp/prod-export.sql`。
7. 演练有任何失败：**停止**，把失败语句与报错写进进度文件，不要上生产，等用户或 Claude/GPT 处理。

## 3. 生产迁移与部署（演练全部通过后）
1. **记回滚书签**：`npx wrangler d1 time-travel info fengqin-crm-prod`，把 bookmark 写进部署记录。
2. 执行迁移（按编号顺序，一个一个来，每个后核对）：
   ```bash
   npx wrangler d1 execute fengqin-crm-prod --remote --yes --file migrations/0034_merge_course_formats.sql
   npx wrangler d1 execute fengqin-crm-prod --remote --yes --file migrations/0035_lesson_unit_minutes.sql
   ```
   核对同第 2 节第 4 步（对生产库只做只读查询）。
3. **紧接着**部署（迁移与代码之间的空窗越短越好）：
   ```bash
   npm run build
   npx wrangler deploy --config deployment/cloudflare/backup-wrangler.toml        # 备份 Worker
   ```
   Pages 有两种方式，任选其一：
   - 普通电脑：`npx wrangler pages deploy dist --project-name fengqin-crm-prod --branch main`；
   - 受限环境（只有 API 令牌，不能上传静态资源）：`node deployment/cloudflare/make-bundle.mjs dist <输出目录>`，再把 `_worker.js`、`_routes.json` 用 API 上传（命令见 `deployment/cloudflare/README.md`「更新站点」）。
4. 不要改 Pages 的环境变量与绑定（`APP_HOST`、`ORIGIN_HOST`、D1/R2、密钥）。

## 4. 上线核对
- `curl https://edu.fantasmearts.com/api/setup` 返回 `{"initialized":true}`；
- 登录页的资源版本与 `dist/tenant.html` 里的 `?v=` 一致；
- 未登录访问 `/api/tools/leads`、`/api/c2/students`、`/api/teacher/today`、`/api/settings/institution` 返回 401；
- 备份 Worker 等下一个 5 分钟触发（北京时间每 5 分钟）后，用 `tools/diagnostics/cf_graphql.py` 查 `workersInvocationsAdaptive` 的 `scriptName: "fengqin-backup-prod"`，新版本 `status` 为 `success`、`errors` 为 0；
- **请用户用真实账号点一遍**：排课（选 45 分钟 × 2 课时，应占 90 分钟，冲突检测按 90 分钟）、课时数 0.5 步进、课程类型形式只有「一对一 / 班课」、课酬标准只有两栏、登录页背景、设置各分区；
- **请用户（主管）导出一次全量备份**（设置 › 数据备份，需主管密码；Antigravity 无法代做）。次日核对 03:00 自动备份在 R2 生成文件。

## 5. 回滚
- 网站有问题：在 Cloudflare Pages 里回滚到上一个成功部署（`GET /accounts/<id>/pages/projects/fengqin-crm-prod/deployments` 找上一个 `success` 的 id，`POST …/deployments/<id>/rollback`），或用上一提交重新构建部署。
- 数据有问题：`npx wrangler d1 time-travel restore fengqin-crm-prod --bookmark=<第 3 节第 1 步的书签>`。注意会丢掉书签之后写入的数据（目前使用量很小）；恢复前先告诉用户。
- 迁移 0034 只改数据、0035 加列并重建触发器：**不要手工 `DROP COLUMN`**，一律用书签恢复。
