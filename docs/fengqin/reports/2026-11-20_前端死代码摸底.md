# 前端死代码摸底报告（基于 00ff864）

## 方法与可信度

- **运行时**：用未压缩打包产物在本地预览（端口 4175，示例数据）中，以主管、老师、学员三种账号，在桌面 1280×800 和 iPhone 13 两种尺寸下逐个点开导航、页签、按钮、抽屉。合计点击约 1500 次，另外单独采样了登录页。采样方式是 CDP 函数级 JS 覆盖率加 CSS 规则使用情况。共 2028 个函数，执行过 1037 个。
- **静态**：
  - 统计每个声明在包内被引用的位置，迭代求「只被死代码引用」的闭包。
  - 按加载顺序模拟全局函数的**覆盖链**：后加载的文件会重新赋值 `app.js` 的函数；还要看原实现有没有被保存进 `const x = fn` 或 `const old = {…}`，以及保存后有没有被调用。
- **交叉判定**：
  - **高置信**：静态（覆盖链或引用闭包）判死，并且运行时确实从未执行。75 项全部一致。
  - **中置信**：运行时没执行，但静态上仍有入口。
  - 判冲突的 5 项都已查明是静态误判（`fq-backup` 一组是正则字面量干扰了解析；`view.js` 被后端 import；`switchControl` 以 `UI.switch` 名义调用；`monthBounds` 被 PWA 预取使用），已从清单中剔除。
- **覆盖盲区**：
  - 没有「仅财务角色」的账号。这类账号的「今天」页会走 `v2.js` 的 `today`。
  - 恢复备份流程、部分设置分区、初始化页没有真正走过。
  - 这些都归入中置信，**没有当成死代码**。

## 二、中置信（运行时没执行，但仍有入口；建议先不动，或者重构时再一并处理）

这些主要是 c2/c3/app 的旧实现。它们被 v2* 用 `old.x(...)` 或 `legacy.x(...)` 保存下来，在「不在完整页面里」（`!inPage(c)`，比如嵌在抽屉、侧栏里）或特定角色、权限时回退调用：

- **app.js**：`studentsPage` 3467–3977（511 行）、`recordForm`、`creditPage`、`classesPage`、`creditForm`、`lessonDetail`、`renderPreview`、`accounts` 等。
- **c2.js**（95% 未执行）：`lessonDetail` 1299–1603、`studentDetail` 494–774、`studentsPage` 284–493、`submissionQueue`、`studentBlocks`、`makeups`、`followupPage`。
- **c3.js**（91% 未执行）：`creditPage` 427–747、`logs`、`auditText`、`accounts`、`settingsPage`、`templatesPage`、`financeRecords`、`followupPage`。
- **v2.js**：`today` 48–274、`financeToday` 1052–1125 是**仅财务角色**的「今天」页，**仍在使用**。
- **v2pay.js**（95% 未执行）：收款、课时包表单（`payForm`、`allocator` 等）。fq-today 和 fq-finance 都在调用，**属于仍在使用的功能**，只是这次没点到。
- **v2t.js**：`makeupPanel`、`renewals`、`followups`、`detail`（补课、续费、跟进的旧页面，fq-today 收件箱的操作仍会打开其中一部分）。
- **yx-settings.js**：`yxsReports`、`yxsStages`、`yxsCourses`、`yxsCalendar`、`yxsProfile` 等。后端接口都还在，属于设置里的少用分区。

要进一步收缩，应该先确认 `inPage()` 为假的场景还有哪些入口；如果都已被新界面取代，就把覆盖链收敛成一层，那时 c2、c3 预计能删掉一半以上。这一步改动面大，**建议和界面重做一起进行**。
