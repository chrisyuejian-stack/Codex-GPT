# 全站接口请求摸底与合并方案（2026-11-20，代码版本 00ff864）

## 测量方法
- 本地用正式构建产物（`TEST_BUNDLE=1`）起预览，写入示例数据：8 名学员、4 位老师、本周课程、线索 6 条。
- 用 Playwright 分别以主管、老师（13700000001）、学员登录，每种角色测 iPhone 13 和桌面 1280×800 两种尺寸。为避免干扰计时，关闭了 Service Worker。
- **每个 `/api/` 请求人为加 150ms 延迟**，这样「必须等上一个请求返回才能发出」的依赖链能清楚显示出来：
  - 串行深度 = 1 + 在它发出之前已经返回的请求的最大深度；
  - D1 往返次数取自响应头 `Server-Timing` 里的 `db;desc="N"`。
- 线上估算口径：
  - 每多一层串行网络往返 ≈ **300–600ms**（国内手机 → EdgeOne 新加坡 → Cloudflare）；
  - 每多一个串行 D1 往返 ≈ **200ms**（Smart Placement 生效前；生效后约几毫秒）。
- 原始数据在 `scratchpad/perfB/crawl-*.json`，脚本是 `perfB/crawl.cjs`。

3. 业务查询本身。

## 二、改进清单（按「每页节省的串行往返」排序）

## 三、建议后端新增的内容（记入 `docs/fengqin/接口变更.md`）

### 3.1 read-batch 白名单扩充（`src/server/read-batch.js:2`）
只加只读 GET，每条仍然按原接口单独校验权限：
```
todo/inbox            （带查询参数）
todo/followups        （带查询参数）
tools/leads           （带查询参数；整体放开 tools/<资源> 的 GET 列表也可以，但要逐个确认没有副作用）
tools/followup_tasks  （带 offset、student_id 参数）
c3/leads-summary
c3/report  c3/receipts  c3/costs-summary  c3/teachers
finance/payroll  finance/settlement  finance/costs  finance/rates
schedule-next
lessons/:id/review    （正则：^lessons\/[A-Za-z0-9_-]+\/review$）
students/:id/fixed-rules
data/student_schedule_blocks
tools/classes
renewal-brand  settings/brand  accounts  logs
```
单批上限 12 条保持不变。前端 `BATCH_EXACT` 和其中的正则按同一份名单更新。

### 3.2 老师今日汇总（支撑第 4 条）
```
GET /api/teacher/today?date=YYYY-MM-DD        （仅 teacher 角色；date 默认北京时间今天）
200 {
  "date": "2026-11-20",
  "today":  [ ...与 GET /api/schedule 相同格式的行（本人、当天）],
  "recent": [ ...前两天到今天的行（用于「还有 N 节没点名」）],
  "reviews": { "<lesson_id>": { ...与 GET /api/lessons/:id/review 相同 } }   // 只含已下课、还没提交的本人主讲课
}
```
只读，权限和原接口相同，内部用 `db.batch` 一次查完。如果前端改用它，老师启动预取就只请求这一条。

### 3.3 `student/comments` 每条补字段（第 6 条后端方案）
每条加 `course_name`、`teacher_name`、`own_attendance`、`start_at`，取自对应课程；原有字段不变。

### 3.4 其他只改后端内部的项（不改接口）
- 第 1 条：机构查询缓存，或并入会话 batch。
- 第 5 条：`c3/report` 6 个月并行查询。
- 第 11 条：`c2/lessons/:id/preview` 内部改为并行。

## 四、建议的实施顺序
1. **前端，马上可做，不依赖后端**：第 2、3、7、8、9、10、13、14、15 条，以及第 6 条的前端方案。改完后老师/学员冷启动和员工启动各少 1 层往返，另有 5 个页面各少 1 层。
2. **后端，收益覆盖所有页面**：第 1、5、11 条，3.1 白名单扩充。
3. **后端新接口**：3.2 老师今日汇总、3.3 点评补字段。完成后前端再切换过去。
