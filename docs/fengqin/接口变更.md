## 保留接口的响应与权限变化

- `GET /api/styles`、`GET /api/styles/:packId/versions/:version`、`GET /api/styles/:packId/versions/:version/assets/:path` 保留反馈卡片共用风格能力。列表默认且仅允许 `doc_type=feedback_card`；plan/article/report 查询返回 404。风格及图片须包含反馈卡片类型、在当前授权范围内且启用，并受 `feedback` 开关控制；纯方案／内容／报告风格不再提供给机构。

- `GET /api/me`：删除 `features.referrals`；`labels.promo`、模块标签、模块开关及 capabilities 不再含 referrals、promo、content、plans、growth_reports、plan_templates、plan_references。控制台 `GET /api/me` 删除 `referrals_enabled`。
- `GET /api/system-messages`：只返回平台公告，`unread_count` 仅统计公告。`POST /api/system-messages/:id/read` 保留公告已读，不再处理 campaign ID。
- `POST /api/read-batch`：不再允许 `promo/recommend` 子请求。
- `GET /api/schedule`、`GET /api/schedule-next`、课次详情及课次导出：移除 `source_course_id`、`source_session_id` 和合作方会议资料来源；普通排课、销课、课酬逻辑保留。数据库通过 0029 移除课次上的合作方外键列。
- `GET /api/parent/children/:studentId/feed` 保留，仅返回教学反馈（含旧点评兼容），不再返回 plan/report 条目。`GET /api/parent/media/:imageId` 保留已授权教学反馈图片；方案／报告中的引用不再授权媒体读取。
- `GET /api/feedback/today`、`POST /api/feedback/:submissionId/:studentId/copied`、曲目维护及出勤／点评接口保留。结构化反馈和反馈 AI 改由 `feedback` 模块开关控制，不再依赖 `growth_reports`。
- `POST /api/ai/settings/propose` 保留，建议的 `payload.affected` 不再包含 `plans_in_progress`。`POST /api/ai/feedback/compose`、`GET /api/ai/usage` 以及平台 AI 设置、机构额度覆盖和用量审计保留。
- `POST /api/ops/tenants`、`PUT /api/ops/tenants` 的可选业务开关只保留 `school_db`，不再接受 content/plans/growth_reports。主管开通接口同样只创建现存模块。
- 平台学科包不再校验／导入 `sample_plans`，方案模板库和样例表已删除。平台风格管理保留通用配置和图片维护，已删除的文档类型不再生成业务示例数据；教学反馈卡片示例保留。
- 图库、机构设置、报价、课程／阶段规则、教学反馈维度、现有备份和恢复流程保留。图库沿用已有私有 R2 键前缀 `promo/:tenantId/gallery/`，这是存储兼容路径，不再对应推广接口。

所有接口仅 supervisor，其他角色403，不能通过自定义权限授权；写请求仍校验同源 Origin。以下为根 `/api` 新契约，不恢复原平台控制台。

| 方法 | 路径 | 输入/响应 |

| POST | `/api/backups/export` | JSON `{password}`；200 返回 `application/vnd.fengqin.backup+json` 附件 `.fqbackup`，前端读取Blob下载。直接用用户密码经 PBKDF2-SHA256 100000次 + 随机盐派生 AES-256-GCM 密钥，随机IV；没有保存密码。文件外层format=fengqin-full-backup-v1、version=1，解密内容带schema_version/migration_version=32、created_at和counts每表行数。文件含全部业务/设置/账号（原密码哈希）/审计与图库，不含会话。服务器另保存 BACKUP_KEY 密文副本 |

| 方法 | 路径 | 约定 |

| GET | `/api/todo/inbox` | 一个请求返回条目、各类型计数和分页；默认 scope=mine，支持 scope=all、type、offset默认0、limit默认50（1–100）、include_snoozed=1。仅返回当前用户有读取权限的内容；student403，教师仅本人主讲的出勤条目 |

| type | 内容与 primary_action 关联id |
|---|---|
| attendance | checkin：已结束待点名/销课课次，lesson_attendance + lesson_id；confirm：已提交待确认的出勤/点评，confirm_submission + submission_id、lesson_id。同一待审课次不再重复生成点名条目 |

| makeup | 学员/教师请假且尚无有效补课安排；schedule_makeup + original_participant_id、lesson_id、student_id；失效/取消的补课不会被当成已完成安排 |

### 主管编辑机构名称、Logo、联系说明（DECISIONS #14，修复密文兼容缺陷）

**接口**：
- `GET /api/settings/institution`：要求 `settings.read`（`settings_scope: "tools"`），主管/教务/财务可读，老师/学员 403。
- `PATCH /api/settings/institution`：除 `settings.read` 外额外要求 `supervisor` 角色（教务/财务/老师/学员均 403）。

**请求体（`PATCH`）**：仅允许以下键，出现其他键（如 `primary_color`）返回 `422`：

```json
{
  "version": 1,
  "name": "枫琴教务中心",
  "logo": "data:image/png;base64,...",
  "contact_text": "咨询请加教务微信"
}
```

- `version`：必填正整数（对应 `tenant_branding.version`，与 `GET/PATCH /api/settings/brand` 共用版本号）；过期或并发冲突返回 `409`，`details.latest` 为最新机构 DTO。
- `name`：可选，非空字符串，trim 后 1–100 字。
- `logo`：可选，`null` 或 `""` 清空；否则须为压缩后的 `PNG` / `JPEG` / `WebP` base64 Data URL，总长 ≤ 180,000 字符，并校验文件头字节与最小长度（PNG ≥ 16 字节含 `IHDR`，JPEG ≥ 4 字节含 `FF D8 ... FF D9`，WebP ≥ 12 字节含 `RIFF...WEBP`），不合法返回 `422`。
- `contact_text`：可选，`null` 或 `""` 清空（数据库列 `tenant_branding.contact_text` 为 `NOT NULL DEFAULT ''`，清空时落空串 `""`）；非空时 trim 后 ≤ 300 字。

**响应体（`GET` / `PATCH` / `409 details.latest`）**：

```json
{
  "version": 2,
  "name": "枫琴教务中心",
  "logo": "data:image/png;base64,...",
  "contact_text": "咨询请加教务微信",
  "primary_color": "#8B7BB5",
  "editable": true
}
```

- **P1 加密修复与兼容性（相对 PR #13 / #17 的阻断级修复）**：
  - `src/server/tools.js:339`（`GET /api/renewal-brand`）与 `src/server/todo-actions.js:198`（`POST /api/renewals/generate`）均以 `decrypt(env, b.contact_text, tenant_id + ":contact")` 解密 `tenant_branding.contact_text`。PR #13 合入 `main` 时 `PATCH /api/settings/institution` 直接写入了明文 `contact_text`，会导致上述两个续费接口抛出 `cipher version` 500 错误且明文落库/落审计。
  - 现已修复：`PATCH /api/settings/institution` 写入非空 `contact_text` 前使用 `encrypt(env, plain, tenant_id + ":contact")` 生成 `v1.` AES-GCM 密文，`GET`/`PATCH`/409 响应统一通过 `decrypt` 返回明文（空串对外仍返回 `null`）。
  - `settingsInstitutionWrite` 审计日志同时脱敏：`before_json` / `after_json` 不再保存 `logo` base64 原图或 `contact_text` 原文/密文，仅记录状态标签（`"已设置"` / `"未更换"` / `"已更新"` / `null`）。
  - `tenant_branding` 已在 `backup-model.js` 全量备份清单中，无需升级备份版本；全量备份导出/恢复后密文与 Logo 完整往返。
