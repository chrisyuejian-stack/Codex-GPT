## 1. 架构说明

端到端验收在仓库现有 Playwright 体系（`playwright.config.mjs` + `scripts/e2e/`）上扩展，不另起炉灶：

- **自动浏览器探测**（`playwright.config.mjs`）：优先读取 `PLAYWRIGHT_CHROME_PATH` 或 `CHROME_PATH`；未指定时先检查 Playwright 自带 Chromium 是否已安装，若未安装则自动回退到系统 `/usr/bin/google-chrome`（及 `/usr/bin/chromium`、`/usr/bin/chromium-browser`），本机与 CI 均可直接运行 `npm run test:e2e`。
- **双视口配置**：
  - `desktop`：`1280×800`
  - `mobile`：iPhone 13 尺寸 `390×844`（`isMobile: true`、`hasTouch: true`、`deviceScaleFactor: 2`）
- **固定场景与固定时间**（`scripts/e2e/scenario.mjs`、`scripts/e2e/server.mjs`）：
  - 全部使用本地内存 SQLite/D1 模拟器与虚构数据（不含真实学员信息与真实密钥）。
  - 服务端与浏览器通过 Playwright `page.clock` 统一固定时间为 `2026-11-12T10:30:00+08:00`（周四上午 10:30），并为学员/老师/线索写入固定递增的 `created_at`，消除列表排序与相对时间抖动。
- **线上巡检原则**：线上只读巡检仅使用 `npm run test:remote:public` 检查公开接口与登录页，绝不在生产环境 `https://edu.fantasmearts.com` 写数据。

## 3. 如何运行

### 3.1 PR 必跑冒烟子集（< 3 分钟）

```bash
npm run test:e2e:smoke
```

如需指定端口（例如避免占用默认 `4380`）或使用打包产物：

```bash
E2E_PORT=4390 npm run test:e2e:smoke
TEST_BUNDLE=1 E2E_PORT=4390 npm run test:e2e:smoke
```

### 3.2 全量端到端验收（含视觉回归）

```bash
npm run test:e2e
```

如需强制指定浏览器路径：

```bash
PLAYWRIGHT_CHROME_PATH=/usr/bin/google-chrome npm run test:e2e
```

### 3.3 查看 HTML / Markdown 验收报告

```bash
npm run test:e2e:report
# 或查看 work/e2e/report.md 与 work/e2e/report.json
```

## 4. 如何更新视觉回归基线

当界面设计有**有意改动**（例如任务 #9 补齐设计稿差距）导致视觉回归失败时：

1. 先查看失败产物 `work/e2e/artifacts/**/diff.png` 确认差异符合预期，而非意外回归。
2. 在与 CI 一致的 Linux 环境下重新生成基线截图：
   ```bash
   npm run test:e2e:update-snapshots
   ```
3. 重新运行 `npm run test:e2e` 确认全部对比通过，再将 `tests/e2e/__snapshots__/` 的更新随 PR 一起提交。

## 5. 已知问题与环境说明

- **当前未发现阻塞产品缺陷**（本次未修改 `src/` 下任何业务代码）。
- **源码模式 vs 打包模式的 SW 缓存差异**：`src/tenant/pwa/sw.js` 仅缓存带版本号参数（`?v=<hash>`）的 `/assets/*` 静态资源；在未打包源码模式下离线测试通过路由拦截 `/api/**` 验证离线数据回退与 `.fq-offline-bar` 提示条，在 `TEST_BUNDLE=1` 打包模式与线上环境下 SW 会完整缓存静态资源与 `/app/` 页面外壳。
- **Node 版本说明**：本机验证环境为 Node `v22.23.5`（带 SQLite 实验特性），`package.json` 声明 `engines.node >= 24`，报告中已如实记录。
