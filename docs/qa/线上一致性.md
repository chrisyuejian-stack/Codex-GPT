## 二、未在本地模拟器覆盖的线上限制及原因

| 限制 / 行为 | 线上规格 | 未覆盖原因 | 缓解与演练方式 |
|---|---|---|---|
| D1 单库容量 / 账号总容量 | 10 GB / 1 TB（Paid） | 内存 SQLite 无物理配额 | 通过生产 D1 监控观察，本项目单机构数据远低于 10 GB |
| D1 单次 SQL 查询时长 / CPU 限流 / 队列过载（7429） | 30 秒查询上限、10 秒窗口资源限流 | 本地 CPU/IO 速度与 Cloudflare Durable Object 不同 | 通过 `LocalD1.queryLimit=40` 与索引测试控制单次请求查询量；线上开启 observability |
| D1 SQLite 表达式深度 / 内部字节码限制（如 `SQLITE_MAX_EXPR_DEPTH`） | Cloudflare 内部编译期宏（与本地 Node SQLite 可能略有差异） | 无法在不编译同版 Cloudflare SQLite 的前提下精确复现 | 通过步骤 3 真实临时 D1 演练验证全部迁移与核心查询 |
| D1 底层 Durable Object 对 `batch()` 中 `PRAGMA defer_foreign_keys` + `DROP TRIGGER` + 重建触发器的精确事务语义 | 真实 D1 运行时行为 | 本地 `node:sqlite` 与 Cloudflare D1 对 DDL 混入 `batch()` 的边界表现需实机确认 | **列入步骤 3 真实临时 D1 必测演练项** |
| R2 单对象 5 GiB 单次上传 / 5 TiB 分片上传 / 同 key 每秒 1 次并发写 | 分布式存储配额与速率限制 | 本地测试不上传 GB 级对象，亦无分布式锁 | 业务层单文件上限远低于 5 GiB（图库 2 MB、备份数 MB） |
